# DoneSpec v1.0.0

## Summary

DoneSpec v1.0.0 is the first stable release target for deterministic completion validation.

AI agents say tasks are done.
DoneSpec verifies they actually are.

DoneSpec is the deterministic completion layer for AI coding agents.

## Why DoneSpec exists

AI coding agents can claim completion while tests fail, required files are missing, forbidden paths changed, or documentation was skipped.

DoneSpec makes completion explicit with a local `done.json` contract, deterministic checks, and CI-friendly exit codes.

## What is included

- `donespec validate` for executing completion contracts
- `donespec validate --strict` for stronger contract hygiene
- `donespec init` for starter project files
- `donespec explain` for inspecting contracts without executing checks
- `donespec schema` for JSON Schema export
- `donespec doctor`, `templates`, and `add-check` for practical authoring support
- JSON output for automation
- GitHub Action support
- documentation for agents, CI, schema usage, editor support, installation, and release verification

## Installation

After v1.0.0 is published:

```bash
python -m pip install donespec
```

Verify:

```bash
donespec --version
donespec --help
```

## Quickstart

```bash
donespec init
donespec validate done.json
donespec validate done.json --strict
```

## Agent integration

Agents do not need DoneSpec embedded in their runtime.

They only need to run the deterministic contract before claiming completion:

```bash
donespec validate done.json --strict
```

If validation fails, the task is not complete. The agent should fix the underlying issue and run validation again.

## GitHub Actions

```yaml
name: DoneSpec

on:
  pull_request:
  push:

jobs:
  donespec:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: xryv/DoneSpec@v1
      - name: Validate completion contract
        run: donespec validate done.json --strict
```

Use the exact tag published for the release when the final GitHub Release is created.

## Stability promise

DoneSpec v1 treats `done.json` as a stable contract format.

v1 changes should be additive where possible. Existing valid v1 specs should not break without a strong reason. Strict mode may reject unsafe or ambiguous specs to preserve contract hygiene.

## What DoneSpec is not

DoneSpec is not:

- an AI framework
- an orchestration platform
- a SaaS service
- an agent runtime
- a dashboard
- a database-backed system
- a memory system
- a plugin marketplace
- an LLM-dependent tool

DoneSpec does not replace tests, CI, review, or judgement.

## Validation before release

The v1.0.0 release candidate should pass:

```bash
python -m ruff check .
python -m ruff format --check .
python -m pytest -q
donespec validate done.json
donespec validate done.json --strict
python -m build
python -m twine check dist/*
```

Package smoke tests should verify local wheel install and PyPI install in clean environments.

## Upgrade notes

No migration steps are expected for valid v1-compatible `done.json` contracts.

Before upgrading release automation, run:

```bash
donespec validate done.json --strict
```
